# Phase 0 — Foundation

Status: **proposed** (2026-11-10). The implementation plan `docs/plans/2026-11-10-phase-0-foundation.md` (rev. 3) refines these decisions after the plan gate.

Phase 0 is mostly sequential. One parallel pair (staging deploy and auth, in separate worktrees) is
defined in the implementation plan. Wide parallel work starts in Phase 1, after the contract and the schema exist.

## Goal

The smallest product that works end to end on every layer:

> A rider opens the web app, sees the list of published trails from the API, signs in with an
> email code or Google, and the API knows who they are.

Everything else (uploads, GPX, maps, editor, gamification) is Phase 1+, built on this.

## Decisions

| # | Decision | Choice | Why |
|---|----------|--------|-----|
| D1 | Monorepo | **pnpm workspaces + Turborepo** | Two apps + shared packages; Turborepo is task caching only, no framework lock-in. Nx adds generators and plugins we do not need. |
| D2 | API | **NestJS 12** (Express 5 adapter) | Explicit modules, DI, guards, OpenAPI from decorators. The portfolio goal. |
| D3 | ORM / migrations | **Drizzle ORM + drizzle-kit** | SQL-first, typed, native `geometry` column for PostGIS points, plain SQL migrations committed to git. Better Auth has a first-party Drizzle adapter. Prisma has no PostGIS types and hides SQL. |
| D4 | Database | **PostgreSQL 17 + PostGIS 3.5**, `geometry(Point/LineString, 4326)`, cast to `::geography` for distances | Same engine as today. Drizzle has a native `geometry` point type but no `geography`; meters come from the cast. LineString paths use a Drizzle `customType`. |
| D5 | Auth | **Better Auth 1.7** inside the API via `@thallesp/nestjs-better-auth` | One auth owner (the API). Plugins: `emailOTP` (6-digit code via Resend) + Google social provider. Session in a first-party cookie. |
| D6 | Web | **Next.js 16** (App Router) | Kept. Server components fetch the API over the internal network. |
| D7 | API contract | **OpenAPI from `@nestjs/swagger` → `openapi-typescript` + `openapi-fetch`** in `packages/api-client` | The web app gets typed calls generated from the API. CI fails if the generated client is stale. |
| D8 | Same-origin routing | One domain; Traefik routes `/api/*` to the API container, the rest to web | No CORS, first-party cookies, simplest auth. Better Auth `basePath: /api/auth`. |
| D9 | CMS | **No Payload in Phase 0** | NestJS owns all data. Payload returns only if editorial content (pages, blog) appears, in its own schema. Moderation lives in the web app behind an `admin` role. |
| D10 | Storage | Cloudflare R2 through the S3 SDK (Phase 1) | Unchanged. Store object keys only, never a provider hostname. |
| D11 | Email | Resend | Unchanged. |
| D12 | Tests | **Vitest** everywhere; API integration tests against a real PostGIS (CI service container); Playwright e2e for the web | One runner. Mocks never stand in for the database. |
| D13 | TypeScript | **Pin TypeScript 6.x** | The NestJS Better Auth adapter declares `typescript ^5.9 || ^6`; TS 7 is not yet supported by it. Revisit when the peer range moves. |
| D14 | Node | **24 LTS** | Matches the current runtime and CI. |
| D15 | Hosting | Coolify on vops-infra: two apps (`api`, `web`) from Dockerfiles + one new PostGIS DB | Same box, same Cloudflare origin lock (Traefik `ipAllowList`) as today. |
| D16 | Data | **No migration of the old database** | Production has one real trail and test rows. Re-create the real trail by hand after launch. |

## Phase 0 schema

- Better Auth tables: `user`, `session`, `account`, `verification` (generated by the Better Auth CLI
  for Drizzle). `user.role`: `rider` | `admin`.
- `trails`: `id`, `slug` (unique), `name`, `description`, `city`, `department`, `difficulty`,
  `type`, `status` (`draft` | `published` | `hidden`), `start_point geometry(Point,4326)`,
  `end_point geometry(Point,4326) null`, `path geometry(LineString,4326) null`,
  `distance_m`, `elevation_gain_m`, `author_id → user.id`, `created_at`, `updated_at`.
- A check constraint keeps coordinates inside Peru's bounding box, so a swapped lat/lng fails loudly
  instead of landing in Kazakhstan.

## Phase 0 API

| Method | Path | Access |
|--------|------|--------|
| GET | `/api/health` | public |
| GET | `/api/trails` | public, published only, filter by `city` |

| GET | `/api/me` | signed-in |

## Security rules carried over

These rules come from the current system and its 283 security tests. Each one gets a test that
proves it can fail.

- Email code: 6 digits, 10-minute TTL, 5 attempts, 60-second cooldown per address, global cap of
  50 codes per 24 h (protects the Resend free tier). A rate-limited response is identical to a
  success, so the endpoint does not reveal whether an address exists.
- Google sign-in keys on the OIDC `sub`, never on the email.
- Codes and tokens are never logged.
- Sessions are revocable; cookies are `HttpOnly`, `Secure`, `SameSite=Lax`.
- The origin accepts only Cloudflare IP ranges.

## CI (GitHub Actions)

`lint` → `typecheck` → `test` (API with a PostGIS service: migrations on a fresh DB, then
integration tests) → `api-client is up to date` → `build` (both apps). CD to staging and the guarded
prod promote follow the same model as the old project (migration first, manual prod dispatch).

## Done when

1. `pnpm dev` runs API + web + local PostGIS (Docker Compose).
2. The web home lists published trails from the API through the generated client.
3. Email-code and Google sign-in work locally; `/api/me` returns the user.
4. Every security rule above has a test that went red when the rule was broken on purpose.
5. CI is green on `main`.

## Phase 1 (parallel, worktrees)

After Phase 0 merges, three feature leads run in their own worktrees:

- **A — Trails & geo:** create/edit trails, path editor API, duplicate detection (100 m), city
  queries.
- **B — Media & GPX:** R2 uploads, EXIF GPS extraction, GPX import (with elevation hysteresis).
- **C — Web UI:** the approved `ui-redesign` prototype on the real API.

Each lead owns its module directories. The schema and `package.json` have one owner per batch to
avoid merge conflicts.
