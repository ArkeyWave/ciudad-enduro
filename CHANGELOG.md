## [Unreleased] - Rider routes (API)

### Added

A non-admin with 3 drafts gets 429 `TOO_MANY_PENDING`; the count and the insert run in one transaction under `pg_advisory_xact_lock(hashtext(author_id))`, so concurrent uploads cannot pass the limit together. Admins have no limit.

- `GET /api/trails` summary (D8): `elevationGainM`, `elevationLossM`, `elevationProfile` (nullable). The detail inherits them from the summary DTO. API client regenerated.

### Security
- Review round 1 of PR #50: the 409 `GPX_DUPLICATE` body gives the `slug` only when the uploader may see that trail (published, own, or admin), also on the race branch (F1). A non-admin's draft count runs once before the GPX parse as a shortcut and again under the lock in the insert transaction (F3). The advisory lock uses two keys, `(7301, hashtext(author_id))`, so it never shares a key with the one-key OTP lock (F4).
- Resource abuse now that riders reach the parser (S2): the GPX is now read with a SAX stream (`saxes` 6.0.0, the parser of jsdom; `fast-xml-parser` removed): only the points of `gpx/trk/trkseg/trkpt` and their `<ele>` are kept, so memory grows with the points, never with other elements, and the 100 000-point cap stops the stream at the first point over it. DOCTYPE, nesting above 100 and the names `constructor`, `__proto__`, `prototype` stay refused (`GPX_INVALID`); all error codes are unchanged. A test parses a 2-point file padded with 2.4 million empty elements (9.6 MB) in a child process with a 48 MB heap (the DOM parser fails it); fake `<trkpt>` tokens in a comment or `<metadata>` change nothing. The round-1 tag budget (`GPX_TOO_COMPLEX`) is removed. `UploadThrottleGuard` runs before the multipart parser: a non-admin gets 429 `TOO_MANY_UPLOADS` after 10 attempts in 10 minutes (sliding window, in memory per API process; a user whose attempts all left the window is forgotten). The 400, 409 and 429 answers of `POST /api/trails` document the `ErrorBodyDto` body (optional `code`, `message` as a string or a list of strings for a validation error, optional `slug`) in OpenAPI; API client regenerated.
- `docs/operations/trails-import.md`: any signed-in user uploads; the author sees own drafts; the new codes.
- `PATCH /api/trails/:slug` stays admin only (a rider gets 403). A rider cannot set `status` or any other unknown field through the multipart body (400, `forbidNonWhitelisted`). Mutation proofs: dropping the author clause, loosening it to any signed-in user, dropping the limit, the advisory lock, the draft filter in the count, or `@Roles` on the queue each turn a test red.

### Security
- Trail mutations need `role = 'admin'` (adapter `@Roles`; anonymous 401, rider 403). `@AllowAnonymous()` moved from the `TrailsController` class to its two GET handlers: on the class the guard returned before it checked roles.
- `OriginGuard` (CSRF): `Origin` must equal `WEB_ORIGIN` exactly, else 403. It runs after the auth guard and before the multipart parser (an order test proves it). SameSite=Lax alone does not stop a same-site POST from another `*.vops.pe` app.
- B-A review round 1: multipart field names must be flat (`fieldNestingDepth: 0`, `fieldArrayIndexLimit: 0`; `name[a]` or `name[4294967294]` → 400 before the DTO). The GPX parser counts every raw `<trk>` and `<trkpt>` (an empty second `<trk/>` → `GPX_MULTI_SEGMENT`, a `<trkpt/>` without coordinates → `GPX_INVALID`; only an empty `<trkseg>` is skipped), and any validator or parser exception (nesting above 100, a name such as `constructor`) is a 400 `GPX_INVALID` without a cause, not a 500. A known file answers `GPX_DUPLICATE` before any slug try, also when all five slugs are taken. The admin view of `GET /api/trails/:slug` uses the same role rule as `@Roles` (`src/auth/roles.ts`).
- B-A final review: the name and the description refuse U+0000 on POST and PATCH (400; Postgres `text` cannot store it, so it was a 500). A test now forces the sha256 unique violation (the race branch) and proves 409 `GPX_DUPLICATE`, 0 trail rows and no `trail_create_failed` line.
- GPX parsing (`fast-xml-parser` 5.12.0): strict UTF-8, any DOCTYPE refused, the document validated first, entities not processed, a constant error code with no snippet of the file. The GPX source is never returned, and a database error is logged as `trail_create_failed` with the Postgres code and constraint only (drizzle's message carries the query parameters, i.e. the GPX).

### Security
- OTP send throttle on the database clock: 60-second cooldown per address and 50 mails per 24 h overall, under an advisory lock; addresses stored only as an HMAC. The send hook runs the CSRF check first (a cross-origin request uses no slot) and grants a one-use permit; the mailer refuses to send without it. Non-sign-in OTP types send nothing. Mail is sent in the background, so the response time reveals nothing.
- Per-IP rate limit keyed on `cf-connecting-ip` (5 sends per 60 s; 3 code checks per 60 s); a spoofed `X-Forwarded-For` is ignored.
- OTP codes stored as HMAC-SHA256 with `OTP_HMAC_SECRET`, not Better Auth's unsalted SHA-256.
- Google: account linking off; the e-mail must be verified on every sign-in (`user.validateUserInfo`, error `google_email_unverified`); `idToken` sign-in bodies refused; Google tokens are never stored (create and update hooks).
- Auth paths are an allowlist: 30 unused Better Auth endpoints answer 404; a test fails when a library upgrade adds one.
- `POST /api/auth/sign-out` runs the CSRF check even without a cookie (a cross-site form could otherwise clear the session cookie).
- Production refuses `http://` values for `BETTER_AUTH_URL` and `WEB_ORIGIN`; a Google token without the `email_verified` claim counts as unverified.
- Auth request bodies are limited to 16 KiB (413; any `Transfer-Encoding` is refused). Sign-up `name` is trimmed and cut to 100 characters; `image` is kept only if it is an `https://` URL.
- `BETTER_AUTH_URL` and `WEB_ORIGIN` must be exact origins (no path, no trailing slash); production checks `https://` with Better Auth's own predicate and refuses `BETTER_AUTH_TRUSTED_ORIGINS`. `/sign-in/email-otp` also runs the CSRF check without a cookie. A failed OTP mail is logged as `auth_background_task_failed` with the error name only.
- Origin check on in every environment (Better Auth turns it off under `NODE_ENV=test`); no CORS headers; `role` cannot be set by the client; no OTP, session token or address in the logs.
