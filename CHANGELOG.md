### Security

The plugin runs before the origin check and the throttle hook (better-auth `dist/api/index.mjs:167-183`): a missing (400 `MISSING_RESPONSE`) or refused (403 `VERIFICATION_FAILED`) token writes no `otp_send_log` row and sends no mail; an unreachable siteverify fails closed (500 `UNKNOWN_ERROR`, 10 s timeout). `TURNSTILE_SECRET_KEY` is required; production refuses Cloudflare's test secrets and `dev-`/`test-` values. The siteverify URL override exists only as a Nest provider for test entrypoints, never as env. Reduces, does not close, global-cap exhaustion (Phase 0 plan §8).

### Security
- OTP send throttle on the database clock: 60-second cooldown per address and 50 mails per 24 h overall, under an advisory lock; addresses stored only as an HMAC. The send hook runs the CSRF check first (a cross-origin request uses no slot) and grants a one-use permit; the mailer refuses to send without it. Non-sign-in OTP types send nothing. Mail is sent in the background, so the response time reveals nothing.
- Per-IP rate limit keyed on `cf-connecting-ip` (5 sends per 60 s; 3 code checks per 60 s); a spoofed `X-Forwarded-For` is ignored.
- OTP codes stored as HMAC-SHA256 with `OTP_HMAC_SECRET`, not Better Auth's unsalted SHA-256.
- Google: account linking off; the e-mail must be verified on every sign-in (`user.validateUserInfo`, error `google_email_unverified`); `idToken` sign-in bodies refused; Google tokens are never stored (create and update hooks).
- Auth paths are an allowlist: 30 unused Better Auth endpoints answer 404; a test fails when a library upgrade adds one.
- `POST /api/auth/sign-out` runs the CSRF check even without a cookie (a cross-site form could otherwise clear the session cookie).
- Production refuses `http://` values for `BETTER_AUTH_URL` and `WEB_ORIGIN`; a Google token without the `email_verified` claim counts as unverified.
- Auth request bodies are limited to 16 KiB (413; any `Transfer-Encoding` is refused). Sign-up `name` is trimmed and cut to 100 characters; `image` is kept only if it is an `https://` URL.
- `BETTER_AUTH_URL` and `WEB_ORIGIN` must be exact origins (no path, no trailing slash); production checks `https://` with Better Auth's own predicate and refuses `BETTER_AUTH_TRUSTED_ORIGINS`. `/sign-in/email-otp` also runs the CSRF check without a cookie. A failed OTP mail is logged as `auth_background_task_failed` with the error name only.
- Origin check on in every environment (Better Auth turns it off under `NODE_ENV=test`); no CORS headers; `role` cannot be set by the client; no OTP, session token or address in the logs.
