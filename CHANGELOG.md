# Changelog

## [Unreleased] - 2026-11-10

### Security
- OTP send throttle on the database clock: 60-second cooldown per address and 50 mails per 24 h overall, under an advisory lock; addresses stored only as an HMAC. The send hook runs the CSRF check first (a cross-origin request uses no slot) and grants a one-use permit; the mailer refuses to send without it. Non-sign-in OTP types send nothing. Mail is sent in the background, so the response time reveals nothing.
- Per-IP rate limit keyed on `cf-connecting-ip` (5 sends per 60 s; 3 code checks per 60 s); a spoofed `X-Forwarded-For` is ignored.
- OTP codes stored as HMAC-SHA256 with `OTP_HMAC_SECRET`, not Better Auth's unsalted SHA-256.
- Google: account linking off; the e-mail must be verified on every sign-in (`user.validateUserInfo`, error `google_email_unverified`); `idToken` sign-in bodies refused; Google tokens are never stored (create and update hooks).
- Auth paths are an allowlist: 30 unused Better Auth endpoints answer 404; a test fails when a library upgrade adds one.
- `POST /api/auth/sign-out` runs the CSRF check even without a cookie (a cross-site form could otherwise clear the session cookie).
- Production refuses `http://` values for `BETTER_AUTH_URL` and `WEB_ORIGIN`; a Google token without the `email_verified` claim counts as unverified.
- Auth request bodies are limited to 16 KiB (413; any `Transfer-Encoding` is refused). Sign-up `name` is trimmed and cut to 100 characters; `image` is kept only if it is an `https://` URL.
- `BETTER_AUTH_URL` and `WEB_ORIGIN` must be exact origins (no path, no trailing slash); production checks `https://` with Better Auth's own predicate and refuses `BETTER_AUTH_TRUSTED_ORIGINS`. `/sign-in/email-otp` also runs the CSRF check without a cookie. A failed OTP mail is logged as `auth_background_task_failed` with the error name only.
- Origin check on in every environment (Better Auth turns it off under `NODE_ENV=test`); no CORS headers; `role` cannot be set by the client; no OTP, session token or address in the logs.

### Added
- CI image smoke run uses `https://` auth URLs: B4's production rule (F16) refuses `http://`, and the B3 smoke run used `http://127.0.0.1:3000`.
- Auth (B4): Better Auth 1.7.18 on `/api/auth` through `@thallesp/nestjs-better-auth` 2.8.0. Sign-in with a 6-digit e-mail code (10-minute TTL, 5 attempts, single use, rotated on resend) or Google (redirect flow only). Auth tables generated by the `auth` CLI (`scripts/auth-cli.ts`, outside the image); migrations `0002_auth`, `0003_otp_send_log`; `trails.author_id` references `user.id` (set null on delete).
- `GET /api/me` (signed-in user); a global guard requires a session on every route except `@AllowAnonymous()` ones (`/api/trails`, `/api/health`). The API client is regenerated with `/api/me`.
- Test-only e2e entrypoint `apps/api/test/support/e2e-main.ts`: the real API, with OTP codes written to `E2E_CODES_FILE` instead of mailed.
- Staging deploy (`docs/operations/deploy.md`): production images `apps/api/Dockerfile` (prod `node_modules`, `dist`, migrations, entrypoint; `BUILD_SHA` baked from the build arg or Coolify's `SOURCE_COMMIT`) and `apps/web/Dockerfile` (Next standalone output), both `node:24-alpine` as `USER node`; `.dockerignore`; `scripts/verify-image.sh` refuses test paths under `/app` and a canary from a build-context `.env` in any image layer. CI `images` job builds, verifies and smoke-runs both images; `deploy-staging` job (push to `main`, Environment `staging`) runs the box's forced-command script `ce-oss-deploy <sha>`, which deploys only commits on `main`, api first, and checks `/api/health` reports that SHA. Live at https://enduro-next.vops.pe behind the Cloudflare origin lock.
- B3 review fixes: `ce-oss-deploy` runs only the reviewed verifier installed on the box and refuses a commit whose `scripts/verify-image.sh` differs, before any deploy; it requires the running api and web images to be `<uuid>:<sha>` and stops an app whose image check fails; the Coolify token never appears in a process argv; lock moved to `/var/cache/ce-oss-deploy` (700). `verify-image.sh` decompresses gzip/zstd layers fully (an early match no longer turns into "not found"), fails closed on any read error, and forbids `.test.` and AI-assistant paths, which `.dockerignore` now also excludes. `deploy-staging` job has `permissions: {}`.
- B3 final-review fixes: `ce-oss-deploy` checks each app right after its own deploy (a failed web deploy cannot leave an unchecked api image live), refuses a rollback to an older `main` commit unless an operator on the box sets `ROLLBACK=1`, re-checks the origin lock after every deploy (direct 403, `cloudflare-only@file` on every router, no host ports; stops both apps on failure), and retries the home page with the revision. Docs: what runs where (the Coolify build runs repo `RUN` steps; risk accepted for staging in plan §8), rollback procedure, follow-ups.
- `pnpm dev` builds `api-client` before the web dev server (the web imports its runtime from `dist/`, which a fresh clone does not have).
- Typed API client (`packages/api-client`): `openapi-typescript` 7.13 renders the committed OpenAPI contract, `createApiClient` wraps `openapi-fetch` 0.17; a type-checked contract test rejects an unknown city. CI `contract` job fails on a stale client.
- Web app (`apps/web`, Next.js 16.4.5, React 19.3.1): the home page lists published trails from the API with Spanish labels (an unknown slug throws); `/api` rewrite only in development. Playwright 1.65.0 e2e on a seeded per-worktree test database, run by the CI `e2e` job.
- The database pool survives a dropped idle connection (no listener made Node exit on a Postgres restart); test-database suffix limited to 26 characters.
- B1 review fixes: the test-database guard rejects URLs with query parameters (`?host=` could redirect the DROP to a remote server); a test proves unknown query parameters get 400; an empty `BUILD_SHA` counts as `unknown`.
- API core (`apps/api`, NestJS 12 + Drizzle + PostGIS): fail-fast env validation that rejects example and `dev-`/`test-` secrets in production; `trails` schema with SRID 4326 geometry columns and Peru bounding-box CHECKs; `GET /api/trails` (published only, `city` filter) and `GET /api/trails/:slug` (draft and unknown slugs answer the same 404); `GET /api/health` with DB status and build revision; OpenAPI emitter that builds the contract without env or database; `db:migrate` and a container entrypoint that migrates before start.
- API test setup: Vitest + SWC, a per-worktree test database recreated on localhost only, mutation-proven tests.
- B0 review fixes: `engineStrict` enforces Node 24; `lint` depends on `^build` so a cached pass cannot hide new errors; `.turbo/` ignored; `db:up` uses `--no-recreate` so parallel worktrees share the dev database safely; TCP health checks; pushes to `main` are never cancelled in CI; Node globals for `.mjs` files; `defineConfig` in the shared ESLint config.
- Phase 0 foundation design: stack decisions, layout, schema, API, carried-over security rules (`docs/architecture/phase-0-foundation.md`).
- Repository scaffold: README, MIT license, `.gitignore` that keeps AI-assistant files out of the public repo.
- Monorepo skeleton: pnpm 12.18.0 workspace, Turborepo 2.11.10, TypeScript 6.0.3, Node 24; shared tsconfig base and ESLint flat config in `packages/config`.
- Local PostGIS 17-3.5 dev database (`docker-compose.dev.yml`, host port 5434) started with `pnpm db:up`.
- CI workflow (`.github/workflows/ci.yml`): install, lint, typecheck, test against a PostGIS service, build.
